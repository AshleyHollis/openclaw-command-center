## Fixed scoring rules

Each child task uses the same evidence milestones. Award the highest fully supported milestone, never points for test volume or repeated passes:

- **0%:** no qualifying completion milestone for this task on the current candidate; prior tooling/evidence may exist.
- **25%:** scope and gaps identified; diagnosis or partial implementation exists.
- **50%:** substantial implementation/focused proof exists, but integration or known material behavior gaps remain.
- **75%:** scoped implementation is integrated and focused checks pass; required wider/independent/real-host qualification remains.
- **100%:** the stated task exit condition is met, with durable evidence for the exact integrated candidate.

A regression can reduce a score and must be explained. A newly discovered bug belongs under an existing task wherever possible; it does not create another denominator item. Log its risk and likely remaining effort even when it does not change a milestone. A genuinely new requirement requires an explicit scope-version change and a before/after comparison. Splitting a task preserves its parent's weight. Do not conceal new scope to keep the number stable.

Parent scores are the arithmetic mean of their fixed child scores. Overall score = 40% native integration + 35% correctness/recovery + 25% qualification/live release. These are explicit planning weights, not measured labor estimates. Display rounded whole percentages with an approximation sign; retain child milestones for reproducibility. Do not alter weights to improve the reported result.

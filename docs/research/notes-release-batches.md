# Separate Notes release lanes

These are Class 3 source preparations, not qualified releases. Review-only
proposals originate at PR #365 (`71425a7422a209f4d34fca3ab612a3ad7419859f`);
current-Topic Note recall originates at PR #376
(`d3b0ea3df9a187ce6dd6047256bf2bd74ac21d93`). They preserve separate scopes.

The stack uses compatibility PR #381 at
`d3f3295ffa736b3010b46986126034c0b8a6a812` (the initially reviewed
`c2fb192665670948fe55ca9ab62c1b237ada39d7` plus the stale harness-identity
assertion correction), preserving deployed CC
`018f4aa10a52c1122f0f045063034dbef05e9d05`, first proposals, then recall.
Recall does not inherently require proposals: this ordering tests their shared
source-service integration and permits serial rollout without mixing their
qualification claims. Native is pinned by that base to
`ea4135dbeced9c393ab4f6ebde8bf3e751ea5fa2`. Compatibility changes remain owned
by that base's source owner; no duplicate pin or runtime patch is included.
The final base package/identity handoff remains required before artifact
qualification. Any reviewed correction to that base must be restacked into both
lanes and independently checked before final source and package freeze.

Production flags stay false. `notes-release-registration.test.mjs` enables only
disposable source copies and checks actual SDK plugin registration under each
independent gate and both together. It is not an enabled package or installed
qualification. Review-only proposals add no model tool, automatic generation,
Note apply/write or schedule. Recall adds only its optional on-demand Notes tool;
general search/rebuild, automatic context, transcripts and cross-Topic retrieval
remain closed.

## Existing operations slot: exact installed scenarios

Use the existing isolated installed-host runner and immutable dependency caches.
Do not provision another full laptop installation or run two host jobs at once.
Supply its measured native 2026.9.9 descriptor, final CC source/build/archive
receipts, fixture baseline digest, gate state and session identities. Each
enabled TEST candidate must have a separate reviewed source head, build digest,
archive SHA256 and CI artifact ID; the production-disabled archive cannot be
claimed as enabled feature proof. No test candidate may activate a producer or
inspect a personal corpus.

The intended TEST-only gate diff for the proposal lane is solely
`noteProposals: false` to `true` in the root build policy; its browser projection
must be generated by the existing build. For the recall lane it is solely
`topicNoteRecall: false` to `true`, retaining the reviewed predecessor's other
gate states. All general search, rebuild, maintenance/write and producer gates
stay unchanged. These diffs are prepared requirements, not built artifacts;
review and identify each actual diff after restacking on the compatibility base.

Use two fictional Topics and exact enrolled folders. Each has `shared.md` at the
root and `nested/source.md`; Topic One also has `target.md` containing an explicit
operator edit. Link distinct fictional open Session incarnations to the Topics.
Populate discovery projections through the existing fixture machinery before
asking for recall. No production rebuild or indexing migration is authorized.

For proposals, `test/support/notes-installed-journey.mjs` exports a scenario that
the existing host runner can call with authenticated RPC, enrolled descriptors,
isolated file-byte reads and its restart callback. It prepares one target and
one or two exact same-Topic sources, fetches context, recovers by saved operation
ID after restart, publishes operator-staged text, recovers comparison, then
discards and confirms text-free retirement after restart. Target and source
bytes must remain unchanged throughout. This helper does not launch a host and
has not been executed against an installed host in this preparation.

Use the existing browser journey in `native-note-proposals.test.mjs` as the
interaction vocabulary: select source, Prepare suggestion, save the displayed
UUID before dispatch, stage Markdown, Review suggestion, inspect Original and
Proposed comparison, recover by saved ID, and Discard. In the installed page,
verify no script interpretation, no automatic request before operator action,
no Chat send, no write/apply button, retained original operator edits, and
cleared text when authority is lost. Repeat stale target/source/folder, source
unavailable versus authority loss, same-ID changed intent, and restart recovery
through actual authenticated bridge transport. Existing source tests do not
substitute for that transport proof.

For recall, verify the optional tool is actually registered and allowed under
the installed native agent policy. Ask on demand in Topic One's linked
Conversation about its root/shared and nested fictional evidence. Record the
actual native invocation/context/cancellation, not a direct service call. Feed
its actual result to `verifyInstalledRecallEvidence` with the known fixture
bytes; verify fresh exact revisions, UTF-16 ranges, bounds and Topic isolation.
An unavailable committed projection must report unavailable; no-matches must
not be presented as proof that source Notes do not exist.

The tool currently publishes a JSON navigation descriptor. The canonical
trusted route/base-path conversion to a model-visible clickable citation
remains an unresolved delivery seam: a hand-authored browser citation is not
proof that actual native model output uses it. Do not enable release until the
actual answer carries the exact supported link. Reuse native `pageHref` and
Markdown routing to the existing Dashboard Topic reader, with `topicId`,
`sourceReferenceId`, `sourcePath`, and `evidenceSourceVersion`. Verify real native
Dashboard delivery, exact reader selection, and the mounted native Chat draft
text/caret/current Session after returning. Do not claim exact in-chat Files
side-pane selection; that is a later enhancement.

After retrieval, edit the cited fictional Note and click the old link. Require
stale refusal before any automatic later-version read; only explicit Open
current Note may show the later revision. Repeat permission loss, removed
reference, folder replacement, Session reset/reassignment and cancellation
during awaited reread. Source excerpts cannot publish from lost authority.
Native memory, Session search/history and consolidation remain unchanged.

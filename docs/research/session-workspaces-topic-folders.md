# Native Session workspaces and Topic Note Folders

Research date: 2026-09-13. Scope: public OpenClaw source at `v2026.9.4`, inspected through GitHub's read-only API. No live installation or user data was inspected. This is a bounded capability review, not a migration qualification.

## Findings

**Several independent Sessions can use the same folder.** Native creation accepts an agent, an optional explicit Session key, and a `cwd`; these are separate inputs. The ordinary local path validates and canonicalizes an existing directory, then stores it as the Session's `spawnedCwd` and `sessionRoot`. It does not reserve exclusive ownership of that directory. Session identity and transcript creation remain separate from the directory binding. Consequently, multiple freshly created Sessions can point to one dedicated Topic Note Folder while retaining independent conversations. Shared files remain shared mutable state; separate transcripts do not isolate concurrent file edits. This conclusion follows from the creation and root owners, rather than an executed integration test. [Creation schema](https://github.com/openclaw/openclaw/blob/v2026.9.4/packages/gateway-protocol/src/schema/sessions-create.ts#L112), [root preparation](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/server-methods/session-create-root.ts#L31), [Session creation owner](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/session-create-service.ts#L1000).

**Group defaults apply to new-session selection, not existing members.** The group owner persists `cwd` and `worktree` on the group catalog row; updating these defaults does not sweep or rebind member Sessions. The UI test demonstrates the “New session in…” action passing the saved folder to `sessions.create`. Assigning an existing Session's `category` changes its presentation grouping, not its execution directory. A group is therefore useful as the native entry point for creating more conversations in a Topic folder, but grouping alone is not a migration. Choose local-folder mode when all conversations should see the same authoritative Notes; a managed Git worktree is a different checkout. [Defaults owner](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/session-groups.ts#L397), [native UI contract](https://github.com/openclaw/openclaw/blob/v2026.9.4/ui/src/e2e/session-management.group-defaults.e2e.test.ts#L143), [category schema](https://github.com/openclaw/openclaw/blob/v2026.9.4/packages/gateway-protocol/src/schema/sessions-patch.ts#L25).

**A Session folder affects execution, not just the Files display.** For ordinary non-subagent Sessions, ingress resolves stored `spawnedCwd` as the run workspace override. Tool construction receives the effective workspace and cwd. Bootstrap behavior is more precise than “everything switches”: the embedded runner explicitly keeps agent bootstrap identity in the configured workspace and layers the selected execution folder's root `AGENTS.md` after it. It does not indiscriminately substitute that folder's persona and memory files. Memory-file injection also has Session and provenance filters; changing cwd does not establish independent Topic memory or change the authoritative conversation. Other harnesses and memory retrieval backends were not exhaustively traced, so their detailed behavior requires qualification before promising Topic-local memory. [Ingress resolver](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/agents/spawned-context.ts#L87), [tool construction](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/agents/embedded-agent-runner/run/attempt-tool-prepare.ts#L194), [bootstrap layering](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/agents/embedded-agent-runner/run/attempt-bootstrap-prepare.ts#L35), [memory filtering](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/agents/bootstrap-files.ts#L336).

**Existing-session rebinding needs care, but “new Sessions are mandatory” is unsupported.** The closed public `sessions.patch` schema has no cwd/workspace field. `sessions.move` moves worker placement between Gateway, profile, and device; its closed destination schema has no local-directory selector. However, `sessions.create` explicitly supports adopting an existing key: the service distinguishes existing rows from new rows and assigns a supplied `spawnedCwd` without a new-row-only guard. That is evidence of a possible native rebinding route, not proof of a safe general migration recipe. The create flow includes ownership checks, lifecycle handling, and special reset/fork paths; unspecified-key main-session creation can reset. Before using adoption, qualify an exact explicit-key, no-initial-turn operation against a fictional existing ordinary Session and verify identity, transcript, root, and later tool behavior. No such operation was executed here. [Patch schema](https://github.com/openclaw/openclaw/blob/v2026.9.4/packages/gateway-protocol/src/schema/sessions-patch.ts#L79), [move targets](https://github.com/openclaw/openclaw/blob/v2026.9.4/packages/gateway-protocol/src/schema/session-placement.ts#L333), [adoption handling](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/session-create-service.ts#L1112), [cwd assignment](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/session-create-service.ts#L1269).

## Product decision versus technical limitation

A workspace is not inherently a security sandbox. Relative tools start there, but absolute access depends on sandbox and permission policy. Native create also requires administrator authority for arbitrary Gateway paths outside configured agent workspaces, and rejects directories outside a sandboxed agent's workspace. [Workspace documentation](https://github.com/openclaw/openclaw/blob/v2026.9.4/docs/concepts/agent-workspace.md), [creation authority](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/server-methods/sessions-create.ts#L284), [sandbox containment](https://github.com/openclaw/openclaw/blob/v2026.9.4/src/gateway/server-methods/session-create-root.ts#L41).

Command Center's dedicated authoritative Note Folder, stable Topic identity, recovery, and read-only first release are accepted product contracts, not evidence that OpenClaw cannot share folders. Native cwd can align with a Note Folder without replacing that ownership metadata. The immediate opportunity is native conversations sharing the verified existing folder, with group defaults supporting future creation. Real remaining work is proving any existing-session rebinding and the desired Files/permission behavior. Replacing Topic lifecycle promises with native grouping would be a deliberate product revision, not a prerequisite imposed by native workspace limitations.

## Backend integration details to retain

- Ordinary native Chat Sessions cannot use plugin-owned `createSessionEntry`, `patchSessionEntry` or `upsertSessionEntry`: those require an owned harness/CLI/ACP runtime. Use the supported authenticated HTTP `dispatchGatewayMethod` contract for create/patch, with the real scoped client and no synthetic operator. Prefer removing obsolete browser adoption rather than relaxing its old external-tab key proof.
- Exact Session readback should use public `getSessionEntry` with latest consistency; absence from a bounded catalog page is not proof of deletion. Stock creation idempotency is memory-local and principal/device-specific. The four-minute retry window alone does not prove safe replay across host restart or a different principal; preserve unknown/recovery-required until ownership can be proven.
- Note recovery must persist filesystem intent and inode/revision evidence before source-to-claim rename, including explicit alias relocation destinations. Existing Topic-operation records can hold this metadata without a schema change or Note bodies. Matching destination text alone does not establish ownership. Required Linux crash proof: edit/move at rename-before-lstat and publication-before-metadata, plus live-owner exclusion, safe retry, foreign identical-byte replacement and cross-directory alias recovery. Catch/rollback hook tests are not equivalent to process-death proof.
- Retain the schedule settings/operation recovery audit under #217: settings currently persist before Cron reconciliation and the completed operation receipt. A failed reconciliation must not lose retry ownership or silently make a reused operation ID stale. The native CAS work protects Cron from stale writers; it does not itself close this product journaling gap.
- Native `ControlUiHost` has no authenticated HTTP body transport in stock 9.2. Asset/tab cookies intentionally carry read-only scopes. Adapt the already-approved narrow relay to a native host-owned request method with validated exact route declarations, current owner/view lifetime, host-supplied authorization, bounded JSON, no redirects and no arbitrary headers or URLs. Preserve server-side exclusive route admission and post-authentication ownership revalidation; do not port iframe grants or expand cookie scopes. An aborted POST is an unknown result requiring journal reconciliation, not an automatic retry.

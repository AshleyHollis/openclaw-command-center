# Native OpenClaw notes: bounded capability assessment

Research date: 2026-09-05. This is an evaluation, not an approved redesign.

## Evidence boundary

Inspected stock `v2026.9.1`, commit `74be8c0d44623711fde78c70bc40f5a633dc4f56`. Local `git diff --name-only v2026.9.1 --` returned no differences for `extensions/memory-wiki`, the inspected agent-memory UI, Session category type, organizer controller, and group RPC descriptors. Citations below pin the upstream tag rather than fork-added APIs. No running installation, private vault, or live Gateway was inspected; no runtime behavior was tested.

## Finding

For the clarified example **Home renovations → linked notes folder → sessions shown underneath**, native Session groups plus a default working directory are the closest existing foundation. A separate agent is not implied. Wiki is optional: ordinary Markdown files can remain in the linked directory without adopting the compiled-wiki model. The unproven piece is an integrated native notes-folder browser/editor alongside those grouped sessions—not basic session grouping.

Native `memory-wiki` can supply a Markdown knowledge vault, compiled retrieval, and Control UI previews. It is **not a verified drop-in replacement** for this app's user-editable, Topic-owned Notes. Its documented role is a compiled knowledge layer, while Command Center currently declares the user's Obsidian documents authoritative. [Wiki role](https://github.com/openclaw/openclaw/blob/v2026.9.1/extensions/memory-wiki/README.md#notes), [current Note contract](../../CONTEXT.md#knowledge-and-conversation).

## Native organization is separate from knowledge scope

Stock Session categories already support organization; their type explicitly distinguishes them from chat groups. Group list/defaults/create/rename/update/delete RPCs exist. These can reduce custom organization work, but a group/default working directory does not establish a per-Topic knowledge boundary. [Category type](https://github.com/openclaw/openclaw/blob/v2026.9.1/src/config/sessions/types.ts#L586), [group RPCs](https://github.com/openclaw/openclaw/blob/v2026.9.1/src/gateway/methods/core-descriptors.ts#L268-L273), [organizer](https://github.com/openclaw/openclaw/blob/v2026.9.1/ui/src/components/session-organizer-controller.ts#L434-L552).

The native group-defaults dialog already lets the user choose a directory and worktree preference; the Gateway validates the directory setting. This is a plausible link from a group to a Markdown folder, not proof that OpenClaw treats that directory as a managed Note Folder. UI nesting is organizational: Session storage remains host-owned, not Markdown transcript files placed beneath the chosen notes directory. Those inspected source files also match the stock tag. [Defaults UI](https://github.com/openclaw/openclaw/blob/v2026.9.1/ui/src/components/session-organizer-controller.ts#L517-L552), [directory validation](https://github.com/openclaw/openclaw/blob/v2026.9.1/src/gateway/server-methods/sessions-groups.ts#L147-L191), [Session storage paths](https://github.com/openclaw/openclaw/blob/v2026.9.1/src/config/sessions/paths.ts#L1-L43).

Command Center's current Topic scope is also not a hard sandbox: explicit-reference and task-necessity cross-Topic retrieval are supported. The requirement is predictable ownership and context selection, not absolute isolation. [Current context policy](../../src/search/context.mjs), [identity ADR](../adr/0001-preserve-topic-identity.md).

## Smallest proposed evaluation

First use one isolated stock installation, a disposable Home renovations directory containing three Markdown files, and one native Session group linked through its default working directory. Create two sessions from that group; verify sidebar nesting, actual session working directories, agent read/write access to the files, group rename/restart behavior, and what native UI exists to browse/edit those files. Do not move transcripts or create an extra agent. Record unsupported operations rather than supplying a custom workaround during the evaluation.

Only if compiled knowledge is wanted, add a separate wiki experiment: external edit then compile/get/search, human-block preservation, page relocation and original-ID lookup, and restart. This is not a prerequisite for the group-plus-folder model.

Then choose explicitly between retaining the existing Topic model or simplifying it to native Session groups plus linked Markdown folders, with only the missing presentation/integration added. Any removal of current identity, archive, recovery, or Topic Search guarantees needs a user decision and domain/ADR update first. This report does not authorize migration or replacement of existing Notes.

| --- | --- | --- |
| Topic / session groups | Native groups store a name and order; session membership is `category`. Groups support rename, member moves, and optional new-session `cwd`/worktree defaults. This already existed in 9.1. [9.2 owner](https://github.com/openclaw/openclaw/blob/v2026.9.2/src/gateway/session-groups.ts), [9.1 owner](https://github.com/openclaw/openclaw/blob/v2026.9.1/src/gateway/session-groups.ts). | A group can present a Topic's linked conversations, but the inspected model does not supply its durable identity, PARA classification, owned Note Folder, Primary Session, or structural-change recovery. `cwd` is an execution default, not Note Folder ownership. ## Security: the new UI is not an equivalent sandbox

Custom native plugin UI is experimental, default-off under Settings → Labs, and requires a Gateway restart/reload when changed. Native modules run in the Control UI's origin and can use the signed-in operator's allowed Gateway methods, including administrative methods for administrators. The implementation forwards native `host.request` to the owning client. This differs materially from Command Center's approved exact-route authenticated iframe relay and unchanged Session grants. Adoption requires an explicit trust decision; declared capabilities must not be described as sandbox confinement. Authenticated native assets also require same-origin HTTPS or browser-trusted loopback, rather than plain HTTP on a LAN hostname. [Feature-plugin security and activation](https://github.com/openclaw/openclaw/blob/v2026.9.2/docs/plugins/feature-plugins.md), [host request owner](https://github.com/openclaw/openclaw/blob/v2026.9.2/ui/src/plugins/control-ui-host.ts).

Release #136755 also broadens omitted cross-agent Session-tool defaults. Preserve the intended visibility/agent-to-agent policy explicitly during migration. This is distinct from an iframe grant or native UI operator scopes; one does not substitute for the other. [Official release](https://github.com/openclaw/openclaw/releases/tag/v2026.9.2).

## Bug fixes and migration prerequisites

The release's off-main-loop transcript reads (#138094) may improve native history responsiveness. The owning change explicitly preserves synchronous APIs and does not make scanning constant-time; its fixture timings cannot qualify Command Center performance. Transcript atomicity and stale-writer fixes (#138412, #138538) protect native Session owners, not Command Center's separate Note and structural-operation journals. They cannot be counted as fixes or acceptance evidence for plugin recovery. [History worker change](https://github.com/openclaw/openclaw/pull/138094), [durable transcript repair](https://github.com/openclaw/openclaw/pull/138412), [live writer admission](https://github.com/openclaw/openclaw/pull/138538).

The seven early-review findings remain tracked, not automatically resolved by this upgrade:

| Finding group | Applicability of 9.2 |
| --- | --- |
| Structural Change completion, Topic Review replay, Topic Analysis scheduling | These are plugin-owned metadata/effect ordering in `src/topics/lifecycle.mjs`, `review-application.mjs` and `analysis-schedule.mjs`. Native Session recovery fixes do not change these owners. |
| Operational Attention production wiring and Degraded Mode gating | Native UI may let us retire some presentation code, but no inspected upstream change connects our Attention sources or changes the blanket gate in `src/ui/app.js`. Reuse must be proven before claiming removal of either finding. |
| Routine approval filtering and recurring Reminder timestamps | Both reproduced defects are in `src/dashboard/service.mjs`. Upgrading the host does not change that projection. Choosing a native replacement would be a separate implementation/spec decision, not a bug fix supplied by the release. |

The separate known Note crash-recovery work likewise remains plugin-owned. This is an owner-based applicability assessment, not a claim that the seven findings have all received runtime reproduction.

An isolated upgrade audit must classify every local host extension as retained, ported, or replaced. In particular, stock 9.2 does not export the locally introduced `tryAcquireExclusiveSqliteCoordinator` from its public SQLite SDK module. The custom iframe bridge is also not established as upstream by the new native UI feature. Do not remove the plugin's writer/recovery dependency or assume its transport works unchanged on a stock upgrade. [Stock SQLite SDK](https://github.com/openclaw/openclaw/blob/v2026.9.2/src/plugin-sdk/sqlite-runtime.ts), [exact tag tree](https://github.com/openclaw/openclaw/tree/v2026.9.2), [public native UI contract](https://github.com/openclaw/openclaw/blob/v2026.9.2/docs/plugins/feature-plugins.md).

Native feature operations are not a drop-in large-Note transport. They use `plugins.sessionAction`, whose payload validator limits individual strings to 64 Ki UTF-16 code units, serialized JSON to 256 KiB, and nodes to 4096. Multi-megabyte Note reads/saves still require an authenticated large-body path or another proven supported mechanism. Browser JavaScript/CSS asset limits are unrelated and cannot justify larger operation payloads. [JSON limits](https://github.com/openclaw/openclaw/blob/v2026.9.2/src/plugins/host-hook-json.ts), [Gateway admission](https://github.com/openclaw/openclaw/blob/v2026.9.2/src/gateway/server-methods/plugin-host-hooks.ts), [feature transport](https://github.com/openclaw/openclaw/blob/v2026.9.2/docs/plugins/feature-plugins.md#define-operations-once).

## Recommendation — proposal, not decision

Run one bounded, isolated 9.2 integration proof before spending on final MVP qualification: native Chat and session navigation, plus a thin Topic overview/Notes panel. Prefer a panel; use `mountDefault` if a workspace wrapper is actually necessary. Keep Topic identity, Note ownership, lifecycle safeguards and recovery in the plugin. Exercise exact Session identity, archive/restore divergence, independent roster pagination, Note drafts and large saves, disconnection/revocation, and view disposal. Compare maintained code removed against new compatibility obligations. Obtain explicit approval before adopting the broader trusted-native-UI boundary.

Only then choose whether to migrate the MVP candidate before final capture or ship the current candidate first. Neither release notes nor this research justify a live upgrade, deleting the current sandbox contracts, or marking acceptance boundaries passed. Memory-wiki and attachment filing remain separate decisions; do not inflate this migration into an unapproved knowledge-store rewrite.

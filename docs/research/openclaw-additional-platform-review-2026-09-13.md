# Additional OpenClaw platform proposals: delivery assessment

Verified 2026-09-13 through public GitHub REST issue/PR metadata, commit comparisons, selected source, and patches. This is a planning assessment, not executed qualification or a security audit of the deployed runtime. No live installation was inspected or changed.

## Decision

Nine of these eleven entries are **open feature issues, not pull requests**. They are not mergeable upstream fixes. Keep them in the roadmap. Of the two open PRs, `socket.drain` is optional future event integration; canonical sandbox read policy deserves a concrete applicability check during the upgrade because it protects an existing execution boundary. Neither replaces Command Center's current filing receipts, Note revisions, Topic ownership, or bounded maintenance scheduling.

Use stable `v2026.9.4` at `3a9d69db306cd7f081e06254cb89c4bcc14a7107` and `release/2026.9.5` at `c6676cb59b2723a62c1281669508994d92f8f7d7` as comparison points; recheck immutable SHAs when implementation starts. An open PR's `merge_commit_sha` can be a synthetic test merge; it is not evidence of a merged release.

## Instructions to carry into the Terra goal

1. Keep all nine feature issues as roadmap references. Do not implement them to finish Chat, attachment filing, or automatic Notes.
2. Preserve existing source-specific operation ownership. Runtime supervision never proves a Note write, file placement, Topic binding, or receipt committed successfully.
3. During upgrade verification, make one bounded #146214 applicability decision using the actual retained OpenClaw execution path and fictional fixtures. If applicable, test lexical deny, denied physical alias, alias change between authorization and I/O, recursive child deny, and non-adopting bridge compatibility. Preserve canonical mutation pinning and asynchronous bounded reads. Use focused Astra help if dependencies or proof remain ambiguous; never import all branch history or broaden filesystem permissions.
4. Treat approval history as already available native functionality. Add no direct ledger reads or broader plugin scope for an optional new audit view.
5. Finish the current fixed acceptance journey and deployment gates before opening new product surfaces. Upstream proposal labels and reported test counts are not local passing evidence.

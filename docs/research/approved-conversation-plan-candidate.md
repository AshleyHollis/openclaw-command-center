The review shows the exact originating Conversation message, outcome, ordered steps, completion criteria and explicit tenant/board destination. Check tracking status after uncertainty; an explicit retry preserves the frozen acceptance. An edited plan cannot reuse its acceptance identity.

The Topic action opens an adjacent review workspace: choose an authoritative assistant transcript entry, enter the exact agreed outcome, steps and criteria, and explicitly choose tenant/board. Review freezes the acceptance before Track. No inference from arbitrary prose or default destination is used. The dashboard reads bindings owned by the authenticated principal, with partial coverage for unavailable sources. Neither surface mounts or rewrites native Chat. Both are behind build-owned `conversationPlans: false`; all four bridge commands remain excluded from first-live commands. The browser fixture connects the review flow to the real CC journal through simulated source/native transports.

## Ownership and representation

`approved-conversation-plan.v1` is separate from the closed email/payment family. `operation_journal` stores the original acceptance, source/membership revision, operator, native destination, scoped create intent and exact card correlation. The immutable acceptance includes the original logical operation ID; another click can have its own immutable operation receipt while resolving the same binding. No table or migration, queue, scheduler, execution lifecycle, notification worker or progress database is added. Generic journal writes cannot replace the reserved family.

The native payload uses supported title, notes, todo, tenant, board and idempotency key. Native title/notes/scope limits are checked before acceptance; no truncation occurs. It deliberately omits an execution object: on the pinned native owner a mode-only object normalizes away, while fabricating execution identifiers would create a misleading execution record. Native todo admission does not Start, specify, decompose or schedule. Native owns subsequent card edits and lifecycle. The accepted CC snapshot remains immutable even after native edits.

Read/reconciliation uses `workboard.cards.list`, not an invented cards.get. Exact card ID, tenant, board, idempotency key and finite updatedAt are checked. Unbound response-loss recovery also verifies the original native title/notes. No attributable native execution receipt is fabricated. Missing cards remain unknown and are not recreated automatically. Explicit unchanged Track retry uses the original idempotency key. Linked attempt projection requires nonempty exact card sessionKey/runId and a matching native attempt; unlinked historical attempts never count as current progress. Done, blocked and review are native status observations only.

## Verified source facts and blockers

Inspected source pair: CC `2253d49b5b90c8c1c8c506a0a38efe300c389da4`, Life `26a9c0faa4124e53ae2eab34291d68a7245f630c`. GitHub main was separately inspected at `291083e4ea381a4edecd56f3fadf9f5b590a3aee`; it is not this feature's baseline. Frozen filing and everyday-workspace branches are untouched.

1. **Exact source-message admission:** the pinned public transcript SDK does expose stable visible `entryId` and message payload. The source adapter uses these with the real CC Session adapter, Topic revision, exact source-reference ownership and synchronous native Session identity. It verifies payload digest around async reads. However, native `withSessionTranscriptWriteLock` is explicitly process-local. Its admission cannot prevent another process replacing a payload or removing the active branch after the read. Workboard #340 can invoke a commit callback, but the public SDK has no bounded synchronous visible-message assertion to invoke there. Production Track explicitly refuses the missing capability before journal reservation or native effects. See the exact [native implementation brief](approved-conversation-plan-native-prerequisites.md).
2. **Open the exact native card:** pinned `ControlUiPageTarget` has no cross-plugin owner field, and the host resolves destinations within the calling plugin. Workboard routes select boards only; internal card details are not a public navigation target. The fictional component tests an injected target only. Production surfaces display the card identity and explain the prerequisite; they do not fabricate a URL or click native DOM. The native brief defines the smallest generic extension.
3. **Explicit human request:** native `question.list` and `exec.approval.list` exist and are read through the existing authenticated native transport. The adapter matches nonempty exact card session/run, pending question or pending approval, and expiry. Approval identity is nested under `request`; its response is a root array. Done/unlinked/expired/unrelated requests are quiet; scope loss is unavailable. The card is reread after requests so a changed card cannot publish old eligibility. The candidate offers navigation to native Chat controls, never a response/execution dispatch. Persistent Attention now reuses the existing episode/occurrence tables with authenticated source guards before and after native verification and at SQLite commit. Immutable native request identity deduplicates concurrent reads and survives restart. A terminal receipt, including terminal-before-pending, permanently prevents that request from reviving. Generic Attention lists, actions, activity and notification projections exclude these owner-scoped records even without adapter registration after restart; only freshly verified references appear in the plan projection and dashboard Focus. Pending-list absence is unknown, not resolution. question.get can verify answered/cancelled/expired questions; native Done, immutable expiry and exact terminal linked runs withdraw obsolete relevance without claiming approval or answer. Explicit requested-result-review has a fictional injected owner test seam, but no qualified native owner and no production RPC; generic blocked/review and progress text are never substituted.
4. **Qualification:** bridge schemas, domain delegation, source adapter and disabled Topic/dashboard composition now exist. Real native Workboard SQLite concurrency, compiled exact-pair and installed browser tests remain required after the native prerequisites. Replaceable progress_card has no run identity and remains excluded from attributable run projection.
